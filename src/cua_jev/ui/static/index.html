THE INSIGHT

把“如何操作”与“用哪种方式操作”拆开。

学术界通常需要收集轨迹，再经过 SFT、强化学习或蒸馏，才能让小模型学会工具选择。CUA-JEV 探索另一条工程路径：把安全动作编译成有限候选，让现成的 Jev 直接承担高频路由决策。

COMMON RESEARCH PIPELINE

先训练，再部署路由策略

  1. 收集 CUA 轨迹
  2. 标注工具与动作
  3. SFT / RL / distillation
  4. 部署小参数策略

适合追求领域最优策略，但数据、训练与迭代成本较高。

CUA-JEV HYPOTHESIS

先约束动作，再即时决策

  1. 读取结构化状态
  2. 生成合法类型化候选
  3. Jev 选择动作与通道
  4. Guard + Verifier 闭环

无需为每个应用训练路由模型，同时保留可检查的概率、执行回执与终态证据。

研究边界“Hybrid 更快”必须建立在相同初态、相同终态验证器和重复成功样本上。本站只呈现真实记录，不用预设数字代替实验结果。

MEASURED EVIDENCE

累积路由优势，而不是单次 API 延迟。

长程任务会反复暴露 GUI 与结构化路线。随着步骤增长，Hybrid 可以把适合后台完成的工作交给 DOM、COM、CLI、MCP 或 API。

Jev 只是 Policy Adapter。规则策略、通用 LLM 或 Computer-Use Agent 也可以使用完全相同的候选动作、执行器和终态验证器。
